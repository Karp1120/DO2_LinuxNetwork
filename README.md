# Linux Networks

Этот репозиторий содержит учебный проект по настройке сетей в Linux на виртуальных машинах.  
В ходе работы были развернуты несколько машин с **Ubuntu 20.04 Server LTS** и выполнены практические задания по адресации, маршрутизации, сетевым утилитам, DHCP, NAT, firewall и SSH-туннелям.

Цель проекта — на практике разобраться с тем, как устроены сети в Linux, как настраиваются IP-адреса, маршруты, правила фильтрации трафика и каким образом машины взаимодействуют между собой в разных сетевых сценариях.

## О проекте

Во время выполнения проекта я последовательно изучил базовые и прикладные сетевые механизмы Linux.  
Работа началась с разбора IP-адресов, масок и подсетей, а затем перешла к более практическим задачам: статической маршрутизации, измерению скорости соединения, настройке firewall, организации сети из нескольких машин, настройке DHCP, NAT и SSH tunnels.

Проект помог не только познакомиться с теорией, но и отработать типичные действия, которые выполняются при настройке сетевой инфраструктуры в Linux.

## Что было сделано

### Part 1. Инструмент ipcalc
- Поднята виртуальная машина `ws1`.
- Изучена работа с IP-адресами и масками.
- Определён адрес сети по заданному IP и префиксу.
- Выполнен перевод масок между:
  - обычной записью,
  - префиксной записью,
  - двоичной записью.
- Определены минимальные и максимальные адреса хостов в сетях с разными масками.
- Разобрано, какие IP относятся к localhost.
- Определены публичные и частные IP-адреса.
- Проверено, какие адреса могут использоваться как адреса шлюза в конкретной сети.

Примеры команд:
`ipcalc 192.167.38.54/13`  
`ipcalc 255.255.255.0`  
`ipcalc 12.167.38.4/8`

### Part 2. Статическая маршрутизация между двумя машинами
- Подняты две виртуальные машины: `ws1` и `ws2`.
- Просмотрены сетевые интерфейсы на обеих машинах.
- Настроены статические IP-адреса:
  - `ws1 — 192.168.100.10/16`
  - `ws2 — 172.24.116.8/12`
- Изменены netplan-конфигурации.
- Применены сетевые настройки.
- Добавлены статические маршруты вручную через `ip r add`.
- Проверена связность машин через `ping`.
- После перезагрузки маршруты добавлены уже через конфигурационный файл netplan.

Примеры команд:
`ip a`  
`sudo nano /etc/netplan/00-installer-config.yaml`  
`sudo netplan apply`  
`ip r add 172.24.0.0/12 via 192.168.100.10`  
`ping 172.24.116.8`

### Part 3. Утилита iperf3
- Разобраны единицы измерения скорости передачи данных:
  - Mbps,
  - MB/s,
  - Kbps,
  - Gbps.
- Измерена скорость соединения между `ws1` и `ws2` с помощью `iperf3`.

Примеры команд:
`iperf3 -s`  
`iperf3 -c 192.168.100.10`

### Part 4. Сетевой экран
- Создан файл `/etc/firewall.sh` на `ws1` и `ws2`.
- Настроены правила firewall с помощью `iptables`.
- Открыт доступ к портам:
  - `22` для SSH,
  - `80` для HTTP.
- Проверены две стратегии настройки правил:
  - сначала запрещающие, потом разрешающие;
  - сначала разрешающие, потом запрещающие.
- Проверена блокировка и разрешение `echo reply`.
- Определена машина, которая не отвечает на `ping`.
- С помощью `nmap` подтверждено, что хост остаётся доступным.

Примеры команд:
`sudo nano /etc/firewall.sh`  
`sudo chmod +x /etc/firewall.sh`  
`sudo /etc/firewall.sh`  
`ping 192.168.100.10`  
`nmap 192.168.100.10`

### Part 5. Статическая маршрутизация сети
- Подняты пять виртуальных машин:
  - `ws11`
  - `ws21`
  - `ws22`
  - `r1`
  - `r2`
- Настроены IP-адреса на всех машинах согласно схеме сети.
- Выполнена проверка сетевой доступности между рабочими станциями и роутерами.
- На роутерах включена IP-переадресация:
  - временно через `sysctl -w`
  - постоянно через `/etc/sysctl.conf`
- Для рабочих станций настроен маршрут по умолчанию.
- На роутерах добавлены статические маршруты к удалённым сетям.
- Проверены таблицы маршрутизации.
- Исследовано, почему маршрут к конкретной сети выбирается вместо маршрута по умолчанию.
- С помощью `traceroute` построен путь от одной машины до другой.
- С помощью `tcpdump` изучено прохождение пакетов через роутер.
- Проверена работа ICMP при обращении к несуществующему адресу.

Примеры команд:
`ip -4 a`  
`ip r`  
`sysctl -w net.ipv4.ip_forward=1`  
`sudo nano /etc/sysctl.conf`  
`traceroute 10.20.0.10`  
`tcpdump -tnv -i eth0`  
`ping -c 1 10.30.0.111`

### Part 6. Динамическая настройка IP с помощью DHCP
- На `r2` настроен DHCP-сервер.
- В файле `/etc/dhcp/dhcpd.conf` указаны:
  - диапазон адресов,
  - маршрутизатор по умолчанию,
  - DNS-сервер,
  - адрес внутренней сети.
- В `resolv.conf` прописан DNS-сервер.
- Перезапущена служба DHCP.
- Проверено, что `ws21` получает IP-адрес автоматически.
- Настроен MAC-адрес для `ws11`.
- На `r1` выполнена выдача IP-адреса с привязкой к MAC-адресу.
- Запрошено обновление IP-адреса на клиенте.
- Сравнены IP до и после обновления.

Примеры команд:
`sudo nano /etc/dhcp/dhcpd.conf`  
`sudo systemctl restart isc-dhcp-server`  
`ip a`  
`sudo dhclient -r`  
`sudo dhclient`

### Part 7. NAT
- На `ws22` и `r1` изменена настройка Apache, чтобы веб-сервер слушал `0.0.0.0:80`.
- Запущен Apache.
- На `r2` настроены правила `iptables` для NAT.
- Проверено, что при определённых правилах маршрутизация блокируется.
- Затем разрешена передача ICMP.
- Настроен **SNAT** для маскирования адресов внутренней сети.
- Настроен **DNAT** для проброса внешнего порта `8080` на веб-сервер `ws22`.
- Проверено TCP-подключение через `telnet`.

Примеры команд:
`sudo nano /etc/apache2/ports.conf`  
`sudo service apache2 start`  
`sudo nano /etc/firewall.sh`  
`sudo /etc/firewall.sh`  
`ping 10.20.0.20`  
`telnet 10.10.0.1 80`  
`telnet 10.100.0.12 8080`

### Part 8. SSH Tunnels
- На `ws22` Apache настроен только на `localhost`.
- Использован **Local TCP forwarding** для доступа к веб-серверу на `ws22`.
- Использован **Remote TCP forwarding** для доступа к тому же серверу с другой машины.
- Проверено подключение через `telnet` на локальный порт.

Примеры команд:
`ssh -L 8080:127.0.0.1:80 user@ws22`  
`ssh -R 8080:127.0.0.1:80 user@ws22`  
`telnet 127.0.0.1 8080`
